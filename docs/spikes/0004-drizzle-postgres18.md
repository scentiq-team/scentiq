# Spike: Drizzle ORM + PostgreSQL 18 (gate of ADR-0004)

- **Date:** 2026-10-26
- **Result:** Passed, 18 of 18 checks. Drizzle stays. No fallback needed.
- **بالعربي:** جربنا كل قاعدة نعتمد عليها بقاعدة البيانات (CHECK، unique جزئي، trigram عربي، قفل الصفوف، منع التعديل) وكلها اشتغلت مع Drizzle. فنكمل بيه.

The spike used three throwaway tables (`spike_products`, `spike_stock`, `spike_audit`), a schema file written with Drizzle, one migration generated by `drizzle-kit`, and two migrations written by hand (`generate --custom`). The spike code is not kept in the repository: the real integration tests of STEP 2 prove the same rules on the real tables, and they run in CI against the official `postgres:18` image.

## Findings that change the plan

1. **Arabic search needs the right database locale.** In a database created with the plain `C` locale, `show_trgm('عود')` returns `{}`: Arabic letters are not treated as word characters, so a trigram index silently finds nothing. With `C.UTF-8` it works. The development database, the CI database and the production database must all be created with a UTF-8 locale that treats Arabic as letters, and the backend ships a test that fails if this is not true (STEP 2).
2. **Drizzle wraps driver errors.** The PostgreSQL error code is on `error.cause.code`, not on `error.code`. A small helper reads both, so constraint violations are classified in one place.
3. **`RESTRICT` and `NO ACTION` report different codes.** A blocked delete under `ON DELETE RESTRICT` is `23001` (restrict violation), not `23503` (foreign key violation). The helper treats both as "still referenced".
4. **Without the lock the system lies.** Without `FOR UPDATE`, 20 buyers were all told "accepted" while only one reservation was recorded, and no CHECK constraint can catch that. Every stock change in Phase 6A therefore starts with a locked read inside a transaction.
5. **The Arabic definite article is part of the word.** Searching `العود` does not match `عود كمبودي`. This is a search-quality task for Phase 5 (normalisation: article, hamza variants, taa marbuta, diacritics), not a database problem.
6. **Migration order matters.** `CREATE EXTENSION pg_trgm` must be a migration that runs before the migration that creates a `gin_trgm_ops` index; `drizzle-kit generate --custom` numbers files in the order they are created.

## Limits of this spike

- It ran on the official PostgreSQL 18.4 binaries, not on the `postgres:18` Docker image (the sandbox has no Docker daemon). CI repeats every check against the image on Ubuntu.
- It was not run on Windows. The partner who runs the project on Windows follows `docs/setup-windows.md`.
